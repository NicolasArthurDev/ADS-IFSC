Nesta atividade, você irá iniciar um backend capaz de fornecer arquivos de acordo com as URI das requisições recebidas.

A primeira versão de seu backend deve usar a [API para criação de um servidor HTTP simples](https://moodle.ifsc.edu.br/mod/page/view.php?id=316709). Ele deve fornecer como resposta os conteúdos de arquivos existentes a partir de um certo subdiretório configurável (ex: _/home/aluno/web_). assim, ele deve atender requisições da seguinte forma:

- Se a URI for /index.html: a resposta deve ter o conteúdo de /home/aluno/web/index.html
- Se a URI for /pics/logo.png: a resposta deve ter o conteúdo de /home/aluno/web/pics/logo.png
- Se a URI não corresponder a um arquivo existente dentro de /home/aluno/web, a resposta deve ter status code 404
- Se a URI corresponder a uma pasta, deve ser retornado um texto html contendo a listagem do conteúdo dessa pasta (nomes de arquivos e subdiretórios). Cada nome de arquivo ou subdiretório deve ter um link associado para o respectivo destino.

Note que, ao retornar o conteúdo de um arquivo, a resposta deve definir o cabeçalho _Content-type_ com o [Internet Media Type](https://en.wikipedia.org/wiki/Media_type) apropriado. A tabela a seguir mostra alguns _media types_:

| **Extensão do arquivo** | **Media Type**  |
| ----------------------- | --------------- |
| .png                    | image/png       |
| .txt                    | text/plain      |
| .html                   | text/html       |
| .js                     | text/javascript |

Uma forma fácil de obter o IMT a partir do nome de um arquivo é com `Files.probeContentType(Path).`

Outro cabeçalho importante é _Content-length,_ que deve informar a quantidade de bytes (octetos) do conteúdo.

#### Como testar

Você deve testar inicialmente seu backend de forma que ele forneça arquivos contidos em um subdiretório configurado. Por exemplo, você pode usar /home/aluno/web, e ali colocar outras pastas e arquivos.
