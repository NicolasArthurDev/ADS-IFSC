O backend, também conhecido como lado do servidor, gerencia a funcionalidade principal de um site. Ele é responsável por armazenar e organizar dados, processar solicitações e se comunicar com o front end. Quando o usuário interage com o front-end, a interação envia uma solicitação para o back-end no formato HTTP. O back-end processa a solicitação e retorna uma resposta.

Quando o back-end processa uma solicitação, possivelmente interage com o seguinte:

- Servidores de banco de dados para recuperar ou modificar dados relevantes
- Microsserviços que executam um subconjunto das tarefas solicitadas pelo usuário
- APIs de terceiros para coletar informações adicionais ou executar funções adicionais

Um back-end pode usar vários protocolos e tecnologias de comunicação para concluir uma solicitação. Além disso, deve ser capaz de processar milhares de solicitações distintas simultaneamente. Técnicas de simultaneidade e paralelismo, como distribuição de solicitações em vários servidores, armazenamento em cache e duplicação de dados, podem ser necessárias para o funcionamento de um backend escalável.

#### Roteamento de requisições

Cada requisição HTTP é caracterizada por duas informações:

- **O método HTTP utilizado**: _GET, POST, PUT, DELETE, ..._
- **A URI requisitada**

Dependendo dessas duas informações, cada requisição deve ser tratada de alguma forma específica. O tratamento de uma requisição significa o processamento realizado para atendê-la, com a geração de uma resposta como resultado. No caso mais simples, todas requisições feitas com um mesmo método HTTP são tratadas da mesma forma.

O roteamento de requisições HTTP é o processo de reconhecimento de requisições e seu encaminhamento para processamento para os endpoints apropriados da aplicação. Basicamente esse processo funciona da seguinte maneira:

1. No servidor são criadas rotas baseadas no método HTTP e URI
2. Quando uma requisição é recebida, o servidor verifica se existe alguma rota correspondente
3. Se uma rota é identificada, o servidor encaminha a requisição para o tratador associado à rota
4. Se não há uma rota, o servido devolve uma mensagem com status HTTP 404 (_não encontrado_) ou 403 _(acesso proibido_)

#### Tratamento de requisições

O tratamento de requisições é feito com unidades de processamento em software, as quais devem ser capazes de gerar uma resposta dependendo das informações contidas em uma requisição HTTP. O processamento envolve extrair informações necessárias da requisição, e efetuar o processamento dependendo da lógica da aplicação, ou do serviço por ela oferecido. Ao final, uma resposta deve ser gerada e retornada para o originador da requisição.

O tratamento de requisições está intimamente ligado ao mecanismo de roteamento de requisições. Uma unidade de processamento de requisições costuma ser chamado de tratador (_handler_).

#### Templates

Um sistema de _templates_ (ou modelos) para web possibilita que desenvolvedores trabalhem com _templates_ para gerar automaticamente respostas a requisições. Isso reutiliza elementos estáticos de página da web enquanto define elementos dinâmicos determinados a partir de parâmetros de requisição da web e da aplicação web em questão.

Um sistema de template da web é composto do seguinte:

- **Um mecanismo de template**: o elemento de processamento primário do sistema, responsável por transformar um template em uma resposta combinando-o com informações fornecidas pela aplicação ao tratar uma requisição
- **Recursos usados como fontes de conteúdo**: qualquer um dos vários tipos de fluxos de dados de entrada, como de um banco de dados relacional, arquivos XML, diretório LDAP e outros tipos de dados locais ou em rede;
- **Templates**: _templates_ da web especificados de acordo com uma linguagem de _template_;

  
Os recursos de _template_ e conteúdo são processados ​​e combinados pelo mecanismo de template para produzir documentos da web. Documentos da web incluem qualquer um dos vários formatos de saída para transmissão pela web via HTTP, HTTPS ou outro protocolo de Internet.

Exemplos de sistemas de _templates_ são:

- [jte (Java Template Engine)](https://jte.gg/)
- [Thymeleaf](https://www.thymeleaf.org/)
- [FreeMarker](https://freemarker.apache.org/index.html)

#### Logging

Um backend atende múltiplas requisições, e usualmente é importante manter registros de dessas requisições. Isso possibilita identificar quais requisições foram realizadas, quando foram atendidas, de onde foram realizadas, e outras informações que podem ser relevantes. Esse conjunto de dados possibilita a realização de auditorias no backend, o que pode ser útil para análise de desempenho e segurança. Outra utilidade de manter tais registros é possibilitar rastrear erros de processamento, ajudando no debug da aplicação web.

O registro de informações sobre a operação de uma aplicação é conhecido como _logging_ (_log_ = diário de bordo). Mais do que uma facilidade para registrar eventos em uma aplicação, logging é uma parte essencial para monitoramento, debugging e manutenção de sistemas.

Alguns sistemas de _logging_ para Java são:

- [Log4j2](https://logging.apache.org/log4j/2.x/)
- [SLF4J](https://www.slf4j.org/)
- [Logback](https://logback.qos.ch/)
- [Java Util Logging (JUL)](https://docs.oracle.com/javase/8/docs/api/java/util/logging/package-summary.html)

#### Autenticação

O acesso a uma aplicação pode precisar ser restringido a um conjunto de usuários previamente cadastrado. Sendo assim, ao acessar uma aplicação um usuário deve informar suas credenciais, e obter uma autorização de acesso. Esse processo pode ser tão simples quanto login e senha, ou complexo como autenticação por dois fatores ou certificação digital. Do ponto de vista do backend, o atendimento de requisições implica poder identificar seu autor e conferir suas restrições de acesso.
